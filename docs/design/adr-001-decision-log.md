# ADR 001: the decision log is our own hash chain, not `libro`

Date: 2026-11-15. Status: accepted. Lane GT-RS1, slice 1 of `engine-and-governance.md` (section 6.8 and 9.2).

## Decision

Write the decision log in this repository (`crates/gatetrain-core/src/declog.rs`, `canon.rs`, about 150 lines of logic) and do not depend on the crate `libro`.

## What was evaluated

`libro` on crates.io, "Cryptographic audit chain: tamper-proof event logging with hash-linked entries and verification", repository `MacCracken/libro`. Checked on 2026-11-15 with the crates.io API:

| criterion | finding | verdict |
|---|---|---|
| licence | `GPL-3.0-only` on 0.92.0 and 0.91.0; `AGPL-3.0-only` on 0.90.0 | **fails**: AGENTS-style rule for this repo (Apache-2.0 public project) allows only MIT / Apache / BSD |
| MSRV | 1.89 | fine, same as ours |
| age and use | first versions 2026-04, 809 downloads | young, little track record |
| fit to our schema | its entries are its own record type with its own store; ours has 14 fixed columns (`seq`, `at`, `actor`, `kind`, ..., `prev_hash`, `hash`), a body hashed as RFC 8785 canonical JSON with `prev_hash + "\n"` as the prefix, and append-only triggers in the ledger file | would need an adapter around a copyleft crate and still would not own the byte format |

The licence alone decides it: linking a GPL-3.0 crate into an Apache-2.0 binary is not allowed, and the design says the canonical bytes must be pinned by us so another implementation can verify an export. The dependency-count and store-fit checks were not pursued past that point.

## Consequences

- The chain is `hash = sha256(prev_hash + "\n" + canonical(body))`, genesis `prev_hash` is 64 zeros, `body` is the entry without `hash`. Canonical form is the RFC 8785 subset in the design (integers only, UTF-16 key order, minimal escapes).
- The format is pinned by `tests/golden/decisions.jsonl`, generated by `tests/golden/gen.py` (hashlib and `json.dumps`, no Rust), and read by a Rust test. A second implementation can check itself against the same file.
- New direct dependencies for this: none beyond the design's list (`sha2`, `serde_json`, `rusqlite`).
- Not done in slice 1 and still the design's: signatures on approvals, `policy_hash` checks against a `policy-change` entry, anchors (a truncated tail is only caught by an anchor), `log export` and `verify --file`.
